CompTIA = Computing Technology Industry Association

---------- OSI ----------

OSI = Open System Interconection

OSI - 7 layer => Application > Presentation > Session > Transport > Network > Data Link > Physical => APSTNDP
All People Seem To Need Data Processing

Layer 1 => Physical = Cable
Sends raw bits through cables, radio, fiber, etc.
Deals with the actual hardware and transmission of bits — 0s and 1s — through cables, fiber optics, or wireless signals. It defines voltages, pin layouts, data rates, 
and physical topology.

Layer 2 => Data Link = MAC (Media Access Control) address on Ethernet - Switching layer (EUI48 - EUI 64)
Transfers data between devices on the same network using MAC addresses.
Takes bits and organizes them into frames. It handles MAC addresses, error detection, and access to the shared network medium. Switches operate here.

Layer 3 => Network = Routing layer = IP (Internet protocol)
Handles IP addressing and routing data between networks.
Handles logical addressing and routing between different networks. IP addresses live here. Routers operate at this layer.

Layer 4 => Transport = Post office - TCP/UDP
TCP = Transmission Control Protocol
UDP = User Datagram Protocol
Provides end-to-end data delivery, reliability, and flow control.
Provides end-to-end communication between applications. It breaks data into segments, manages reliability, ordering, error recovery, and flow control. 
TCP and UDP are here. Port numbers are used.

Layer 5 => Session = Comunication management between devices - SSL/TLS
Establishes, manages, and ends communication sessions.
Establishes, maintains, and terminates sessions between applications. It also handles synchronization and checkpoints so a long transfer can resume if interrupted.

Layer 6 => Presentation = Charecter encoding / application encryption 
Handles data format, encryption, compression, and translation.
Ensures data is in a usable format. It handles translation, encryption/decryption, and compression. For example, converting text to ASCII or encrypting with TLS.

Layer 7 => Application = HTTP/HTTPS/FTP/DNS/POP3
Provides network services directly to applications.
The layer closest to the user. It provides network services to applications like web browsers, email clients, and file transfer tools. HTTP, DNS, SMTP, and FTP operate here.

---------- Networking Devices ----------

Router
A router connects different networks together and directs data packets between them based on IP addresses. It sits at the boundary of your network (e.g., between your home/office LAN 
and the internet) and makes decisions about the best path for traffic to travel. Routers operate at Layer 3 (Network layer) of the OSI model.

Switch
A switch connects multiple devices within the same local network (LAN) and forwards data only to the specific device it's intended for, using MAC addresses. This is more efficient 
than older hubs, which broadcast to every device. Switches operate at Layer 2 (Data Link layer), though "Layer 3 switches" also do basic routing.

Firewalls
A firewall monitors and controls incoming/outgoing network traffic based on predefined security rules, acting as a barrier between trusted internal networks and untrusted external 
ones (like the internet). It can be hardware, software, or both, and works by inspecting packets and blocking or allowing them based on IP address, port, protocol, or more advanced 
criteria (application-aware firewalls).
Layer 3 => can work as reouter

IDS/IPS (Intrusion Detection/Prevention Systems)
IDS (Intrusion Detection System): Passively monitors network traffic for suspicious activity or known attack signatures, and alerts administrators — it doesn't block anything itself.
IPS (Intrusion Prevention System): Sits inline with traffic flow and actively blocks or drops malicious traffic in real time, in addition to detecting it.

They're often combined in modern security appliances (and frequently built into next-gen firewalls).

Load Balancer
A load balancer distributes incoming network traffic across multiple servers, so no single server gets overwhelmed. This improves reliability (if one server fails, traffic is rerouted 
to healthy ones) and performance/scalability for high-traffic applications. Common algorithms include round-robin, least connections, and IP hash.

Proxies
A proxy server acts as an intermediary between a client and the internet. Requests go through the proxy, which forwards them on the client's behalf. Benefits include:

Anonymity/privacy — hides the client's real IP address
Caching — stores frequently requested content for faster access
Content filtering/access control — often used in corporate/school networks
Reverse proxies do the opposite: they sit in front of servers, forwarding client requests to backend servers (often paired with load balancing).

NAS and SAN
NAS (Network Attached Storage): A dedicated storage device connected to a network, giving multiple users/devices file-level access to shared storage over standard Ethernet — it's 
like a shared network drive. Simple to set up, good for file sharing.
SAN (Storage Area Network): A dedicated, high-speed network that provides block-level storage access, typically used by servers needing very fast, low-latency access to raw 
storage (e.g., for databases or virtualization). More complex and expensive, often using Fibre Channel or iSCSI.

Wireless LAN Controller (WLC)
A Wireless LAN Controller centrally manages multiple wireless access points (APs) across a network — commonly used in enterprises or campuses with many APs. Instead of configuring 
each AP individually, the WLC handles configuration, security policies, channel/power management, load balancing across APs, and roaming (so a device moving between APs keeps a 
stable connection) — all from one place.

========== Extra ==========
Router
What it does: Connects two or more different networks (e.g., your LAN to the internet, or two branch offices to each other) and forwards data packets between them based on IP addresses. 
It reads the destination IP of each packet and decides the best path using a routing table.

OSI Layer: Layer 3 (Network layer)

How it works:

Maintains a routing table of known networks and the "next hop" to reach them
Uses routing protocols to build/update that table dynamically: RIP, OSPF, EIGRP, BGP (BGP is the protocol that runs the entire internet's backbone routing)
Performs NAT (Network Address Translation) — translates private internal IPs to a public IP so multiple devices can share one internet connection
Can enforce basic ACLs (Access Control Lists) to permit/deny traffic

Types:

Edge/border routers — connect your network to an ISP or another network
Core routers — route traffic within a large network backbone, very high throughput
Wireless routers — combine routing + Wi-Fi access point + switch (common in homes)
Virtual routers — software-based, run in cloud environments (e.g., AWS Virtual Private Gateway)

Key point: Routers connect different networks; switches connect devices within the same network.


Switch
What it does: Connects multiple devices within a single LAN and intelligently forwards traffic only to the specific device it's addressed to, rather than broadcasting to everyone.

OSI Layer: Layer 2 (Data Link) — uses MAC addresses; Layer 3 switches also route between subnets using IP.

How it works:

Builds and maintains a MAC address table mapping each port to the device connected to it
Forwards frames only out the correct port (unlike a hub, which floods every port) — this drastically reduces collisions and improves performance
Supports VLANs (Virtual LANs) to logically segment a physical network into isolated broadcast domains
Uses STP (Spanning Tree Protocol) to prevent loops when there are redundant links

Types:

Unmanaged switches — plug-and-play, no configuration, used in small/home setups
Managed switches — configurable (VLANs, QoS, port security, monitoring), used in businesses
Layer 3 switches — combine switching + basic inter-VLAN routing, common in enterprise cores
PoE (Power over Ethernet) switches — deliver power and data over the same cable, used for IP phones/cameras/APs


Firewalls
What it does: Monitors and controls incoming/outgoing traffic based on security rules, acting as a barrier between trusted and untrusted networks.

OSI Layer: Varies by type — from Layer 3/4 (basic packet filters) up to Layer 7 (application-aware firewalls)

How it works / types:

Packet-filtering firewalls — inspect header info (source/dest IP, port, protocol) against static rules; fast but basic
Stateful inspection firewalls — track the state of active connections, so return traffic for an established session is automatically allowed
Proxy/application-layer firewalls — inspect actual application data (e.g., HTTP content), not just headers
Next-Generation Firewalls (NGFW) — combine traditional filtering with deep packet inspection, intrusion prevention, application awareness, and SSL inspection
Web Application Firewalls (WAF) — specifically protect web apps from attacks like SQL injection and XSS

Deployment forms: Hardware appliance, software (host-based), or cloud-native (e.g., cloud security groups)

Common vendors: Cisco ASA/Firepower, Palo Alto, Fortinet, pfSense (open source)


IDS / IPS
IDS (Intrusion Detection System):

Passively monitors traffic (usually on a mirrored/SPAN port), analyzes it against known attack signatures or behavioral baselines, and alerts administrators
Does NOT sit inline — it doesn't block traffic itself
Types: NIDS (network-based, monitors traffic) vs HIDS (host-based, monitors a single machine's logs/files)

IPS (Intrusion Prevention System):

Sits inline with the traffic path, so it can actively block, drop, or reset malicious connections in real time
Detection methods:
Signature-based — matches traffic against a database of known attack patterns (fast, reliable for known threats, blind to new/zero-day attacks)
Anomaly-based — builds a baseline of "normal" behavior and flags deviations (catches novel attacks, more false positives)
Policy-based — flags anything violating a defined security policy

Note: Modern NGFWs typically have IDS/IPS functionality built in as one module rather than as separate boxes.


Load Balancer
What it does: Distributes incoming client requests across a pool of backend servers, improving performance, reliability, and scalability.

OSI Layer:

Layer 4 load balancing — distributes based on IP/port (TCP/UDP), fast, doesn't inspect content
Layer 7 load balancing — inspects application-level data (HTTP headers, URLs, cookies) to make smarter routing decisions

Common algorithms:

Round robin — cycles through servers in order
Least connections — sends new requests to the server with fewest active connections
Weighted round robin/least connections — accounts for servers with different capacities
IP hash — routes based on client IP, useful for session persistence ("sticky sessions")
Least response time — picks the server currently responding fastest

Key features:

Health checks — automatically detects and routes around failed servers
SSL termination — decrypts HTTPS traffic at the load balancer so backend servers don't have to
High availability — often deployed in active/passive pairs to avoid becoming a single point of failure

Examples: F5 BIG-IP, HAProxy, NGINX, AWS Elastic Load Balancer, Cloudflare Load Balancing


Proxies
What it does: Acts as an intermediary that relays requests between a client and a destination server.

Forward proxy (client-side):

Sits in front of clients, forwarding their requests out to the internet
Client's real IP is hidden from the destination server
Used for: content filtering (schools/offices), caching frequently accessed content, bypassing geo-restrictions, enforcing acceptable-use policies

Reverse proxy (server-side):

Sits in front of one or more backend servers, forwarding client requests to them
Backend servers' real IPs are hidden from clients
Used for: load balancing, SSL termination, caching, compression, protecting servers from direct exposure to the internet, serving as a single entry point for microservices
Examples: NGINX, HAProxy, Cloudflare, Apache with mod_proxy

Transparent vs. anonymous vs. high-anonymity proxies — differ in how much they reveal about the original client to the destination.


NAS and SAN
NAS (Network Attached Storage):

A dedicated file-storage device connected to the network, accessed by multiple users/devices at the file level (like a shared network drive)
Uses standard Ethernet and file-sharing protocols: NFS (Linux/Unix), SMB/CIFS (Windows), AFP (older Mac)
Simple to set up and manage, relatively affordable
Good for: shared file storage, backups, media serving, small-to-medium business file shares
Often built with RAID for redundancy

SAN (Storage Area Network):

A dedicated, high-speed network that provides shared storage at the block level — servers see it as if it were a locally attached disk
Uses specialized protocols/hardware: Fibre Channel (FC), iSCSI (block storage over standard IP/Ethernet), FCoE
Requires dedicated switches (FC switches) for the storage fabric in traditional deployments
Higher performance, lower latency, more complex and expensive
Good for: databases, virtualization (VMware/Hyper-V datastores), transaction-heavy enterprise applications


Wireless LAN Controller (WLC)
What it does: Centrally manages, configures, and monitors multiple wireless access points (APs) across an organization, instead of configuring each AP individually.

Key functions:

Configuration management — pushes SSIDs, security settings, and channel/power settings to all APs at once
RF management — automatically adjusts channel selection and transmit power to minimize interference (Radio Resource Management)
Seamless roaming — lets devices move between APs without dropping their connection or re-authenticating
Load balancing across APs — steers clients to less-congested APs
Security enforcement — manages authentication (WPA2/WPA3, 802.1X/RADIUS), rogue AP detection
Guest network management — captive portals, guest VLANs, bandwidth throttling

Architectures:

Hardware controller — a dedicated physical appliance on-premises (traditional enterprise model, e.g., Cisco WLC)
Cloud-managed — APs are managed via a cloud dashboard, no physical controller needed (e.g., Cisco Meraki, Aruba Central, Ubiquiti UniFi)
Controller-less/distributed — intelligence is distributed among the APs themselves rather than a central box

Typical use case: Campuses, hospitals, hotels, large offices — anywhere you have dozens to thousands of APs that need consistent, centralized policy.


---------- Networking Functions ----------
CDN = Content Delivery Network
What it is: A geographically distributed network of servers that cache and deliver content (web pages, images, videos, scripts) from a location physically close 
to the end user, rather than from one central origin server.

How it works:

The origin server's content is replicated across many edge servers (Points of Presence, or PoPs) worldwide
When a user requests content, DNS-based routing or Anycast sends them to the nearest or best-performing edge server
That edge server serves a cached copy if available; otherwise it fetches from the origin and caches it for future requests

Benefits:

Lower latency — content travels a shorter physical distance
Reduced origin server load — most requests are absorbed by edge caches
Better reliability/DDoS resilience — traffic is spread across many servers instead of hitting one
Bandwidth cost savings for the site owner

Examples: Cloudflare, Akamai, Amazon CloudFront, Fastly


VPN = Virtual Private Network
What it is: A technology that creates an encrypted, private "tunnel" over a public network (usually the internet), allowing a device to securely connect to another
 network as if it were directly attached to it.

How it works:

Traffic between the client and a VPN server/gateway is encapsulated and encrypted using a tunneling protocol
The VPN server decrypts traffic and forwards it to its destination, masking the client's real IP and location

Common protocols:

OpenVPN — open-source, highly configurable, uses SSL/TLS
IPsec — a suite of protocols often paired with L2TP or used standalone (IKEv2/IPsec)
WireGuard — modern, lightweight, fast, growing in popularity
SSL/TLS VPNs — often browser-based, used for remote access to specific apps

Types:

Remote access VPN — individual users connecting to a private network (e.g., employees working from home)
Site-to-site VPN — connects two entire networks/offices together permanently

Uses: Securing traffic on public Wi-Fi, remote access to corporate resources, bypassing geo-restrictions, privacy from ISPs


QoS = Quality of Servvice
What it is: A set of technologies/techniques used to manage network resources by prioritizing certain types of traffic over others, ensuring critical applications
 get the bandwidth and low latency they need.

Why it matters: Not all traffic is equally sensitive — a video call or VoIP call suffers badly from delay/jitter, while a file download can tolerate it. QoS lets
 networks prioritize accordingly.

Key mechanisms:

Classification & marking — tags packets (e.g., using DSCP or 802.1p markings) so devices along the path know how to treat them
Queuing/scheduling — high-priority traffic is placed in priority queues and serviced first (e.g., Weighted Fair Queuing)
Traffic shaping/policing — controls the rate of traffic to smooth bursts or enforce bandwidth limits
Congestion avoidance — techniques like RED (Random Early Detection) to prevent queue overflow

Common metrics QoS manages:

Bandwidth — capacity
Latency — delay
Jitter — variation in delay
Packet loss

Typical use cases: Prioritizing VoIP/video conferencing over general web browsing on a corporate network, or prioritizing gaming traffic on a home router.


TTL = Time To live
What it is: A field in a packet (or a DNS record) that limits how long the data is valid or how many "hops" it can traverse before being discarded. It has two
 very different but related uses:

1. TTL in IP packets:
An 8-bit field in the IP header, set by the sending device (commonly 64, 128, or 255)
Each router that forwards the packet decrements the TTL by 1
If TTL reaches 0, the packet is discarded and an ICMP "Time Exceeded" message is sent back
Purpose: prevents packets from looping forever due to routing errors
Bonus use: the traceroute/tracert tool exploits this — it sends packets with increasing TTL values (1, 2, 3...) to map every hop along a path

2. TTL in DNS records:
Specifies (in seconds) how long a DNS resolver/caching server should cache a record before re-querying the authoritative server
Short TTL (e.g., 60s) → changes propagate fast, but more DNS lookups/load
Long TTL (e.g., 86400s = 24h) → less load, but changes take longer to propagate globally
Default TTL for macos/linux is 64 hops
Default TTL for Windows is 128 hops


DNS = Domain Name System (the command is dig)
What it is: The system that translates human-readable domain names (e.g., example.com) into IP addresses that computers use to identify each other — often called
 "the phonebook of the internet."

How a lookup works (simplified):

Your device checks its local cache; if not found, asks a recursive resolver (often your ISP's or a public one like Google's 8.8.8.8 or Cloudflare's 1.1.1.1)
The resolver queries a root server → which points to the correct TLD server (e.g., .com)
The TLD server points to the domain's authoritative name server
The authoritative server returns the actual IP address
The resolver caches the answer (per the TTL) and returns it to your device

Key record types:

A record — maps a domain to an IPv4 address
AAAA record — maps a domain to an IPv6 address
CNAME — alias, points one domain name to another
MX — mail server for the domain
NS — specifies the authoritative name servers
TXT — arbitrary text, often used for verification (e.g., SPF, DKIM for email security)
PTR — reverse lookup, IP → domain name

DNS over HTTPS/TLS (DoH/DoT): newer standards that encrypt DNS queries for privacy, since plain DNS is unencrypted by default.

NAT (Network Address Translation)
Translates private internal IP addresses to a public IP (and back), allowing many devices to share one public IP. Covered briefly under routers, but worth 
calling out on its own — it's foundational to how home/office networks connect to the internet.

DHCP (Dynamic Host Configuration Protocol)
Automatically assigns IP addresses (and other settings like DNS server, gateway) to devices joining a network, so you don't have to configure each device manually.
 Uses a "DORA" process: Discover → Offer → Request → Acknowledge.

ARP (Address Resolution Protocol)
Resolves an IP address to the physical MAC address of a device on the local network — needed because Ethernet switches forward frames by MAC address, not IP.

ICMP (Internet Control Message Protocol) / Ping
Used for network diagnostics and error reporting — ping uses ICMP Echo Request/Reply to test reachability and measure round-trip time; also used for the TTL-exceeded 
messages mentioned above.

MTU (Maximum Transmission Unit)
The largest packet size (in bytes) that can be transmitted over a network segment without fragmentation. Standard Ethernet MTU is 1500 bytes; exceeding it causes 
fragmentation or drops depending on settings.

Subnetting & CIDR
The practice of dividing a larger network into smaller sub-networks, written in CIDR notation (e.g., 192.168.1.0/24), where the number after the slash indicates 
how many bits are used for the network portion.

Port numbers
A 16-bit number (0–65535) identifying a specific service/process on a device — e.g., port 80 (HTTP), 443 (HTTPS), 22 (SSH), 53 (DNS). Combined with an IP address,
 a port forms a full socket.

SSL/TLS
Cryptographic protocols that encrypt data in transit (the "S" in HTTPS). TLS is the modern successor to SSL. Involves a handshake to establish encryption keys 
and verify server identity via certificates.

Bandwidth vs. Throughput vs. Latency

Bandwidth — theoretical maximum capacity of a link
Throughput — actual data successfully transferred
Latency — time delay for data to travel from source to destination


IP (Internet Protocol)

What it is: IP is the core protocol of the internet, responsible for addressing and routing packets of data so they get from a source device to a destination 
device across interconnected networks. It's a Layer 3 (Network layer) protocol and is "connectionless" — each packet is routed independently, with no guaranteed 
delivery (that reliability is handled by TCP on top of it, forming the well-known TCP/IP stack).

IPv4 vs IPv6

IPv4:

32-bit address, written as four decimal octets separated by dots: 192.168.1.1
Provides about 4.3 billion unique addresses — long since exhausted for direct public allocation, which is why NAT became essential
Still the dominant protocol in most networks today

IPv6:

128-bit address, written as eight groups of hexadecimal digits separated by colons: 2001:0db8:85a3:0000:0000:8a2e:0370:7334 (can be abbreviated, e.g., ::1 for loopback)
Provides an effectively inexhaustible number of addresses (340 undecillion)
Designed to eliminate the need for NAT, simplify routing, and include built-in support for features like auto-configuration and improved security (IPsec was originally 
mandatory in the spec)
Adoption is growing but IPv4 remains widespread, so most networks run dual-stack (both simultaneously)
Address Structure & Classes (IPv4)

Historically, IPv4 addresses were divided into classes:

Class A: 1.0.0.0 – 126.255.255.255 (large networks, /8)
Class B: 128.0.0.0 – 191.255.255.255 (/16)
Class C: 192.0.0.0 – 223.255.255.255 (/24, common for small networks)
Class D: multicast addresses
Class E: reserved/experimental

This rigid class system has largely been replaced by CIDR (Classless Inter-Domain Routing), which allows flexible subnet sizes using a prefix length (e.g., /24, /16) 
instead of fixed classes.

Public vs. Private IP Addresses
Public IPs — globally unique, routable on the internet, assigned by ISPs/regional registries (ARIN, RIPE, etc.)
Private IPs — reserved ranges for internal/local networks, not routable on the public internet:
10.0.0.0 – 10.255.255.255 (10.0.0.0/8)
172.16.0.0 – 172.31.255.255 (172.16.0.0/12)
192.168.0.0 – 192.168.255.255 (192.168.0.0/16)
Devices with private IPs reach the internet via NAT on a router, which translates their address to the router's public IP
Static vs. Dynamic IP
Static IP — manually assigned, doesn't change; used for servers, printers, devices needing a consistent address
Dynamic IP — assigned automatically (usually via DHCP), can change over time; typical for most client devices
Subnetting

Breaking a large network into smaller, more manageable subnetworks using a subnet mask (or CIDR prefix). For example, 192.168.1.0/24 has a subnet mask of 255.255.255.0, 
giving 256 addresses (254 usable for hosts, with the first reserved as the network address and the last as the broadcast address). Subnetting improves security, 
reduces broadcast traffic, and allows logical organization (e.g., separate subnets for different departments).

Special/Reserved Addresses
127.0.0.1 — loopback, refers to the local device itself
0.0.0.0 — represents "any address" or an unassigned address
255.255.255.255 — limited broadcast address, sent to all devices on the local network
169.254.x.x — APIPA (Automatic Private IP Addressing), self-assigned when DHCP fails
How IP Fits with Other Protocols

IP itself only handles addressing and best-effort delivery — it doesn't guarantee packets arrive, arrive in order, or arrive at all. That's why it's typically paired with:

TCP (Transmission Control Protocol)

What it is: A connection-oriented, reliable transport-layer protocol that guarantees data is delivered accurately, in order, and without loss between 
two devices. It runs on top of IP (hence "TCP/IP").

Key characteristics:

Connection-oriented — establishes a connection before sending data via the three-way handshake:
Client sends SYN
Server responds SYN-ACK
Client sends ACK
Reliable delivery — every segment is acknowledged; lost segments are retransmitted
Ordered delivery — segments are numbered (sequence numbers) and reassembled in the correct order at the destination, even if they arrive out of order
Flow control — uses a "sliding window" so a fast sender doesn't overwhelm a slow receiver
Congestion control — dynamically adjusts sending rate based on network conditions (algorithms like Reno, Cubic)
Error checking — checksums detect corrupted data

Trade-off: All this reliability adds overhead and latency compared to UDP.

Used for: Web browsing (HTTP/HTTPS), email (SMTP/IMAP), file transfer (FTP), anything where accuracy matters more than raw speed.

UDP (User Datagram Protocol)

What it is: A connectionless, lightweight transport-layer protocol that sends data ("datagrams") without establishing a connection first and without 
guaranteeing delivery, order, or error correction.

Key characteristics:

No handshake — just sends data immediately, lower latency
No guaranteed delivery — packets can be lost with no automatic retransmission
No ordering guarantee — packets may arrive out of sequence
Minimal overhead — smaller header (8 bytes vs. TCP's 20+ bytes), faster processing
Basic checksum exists but error recovery is left to the application if needed

Used for: DNS lookups, video/audio streaming, VoIP, online gaming, live broadcasts — anywhere speed and low latency matter more than perfect 
delivery (a dropped video frame is less disruptive than a delayed one).

Together, these form the TCP/IP model, the foundational framework the entire modern internet is built on.


NFV (Network Function Virtualization)

What it is: An approach that replaces dedicated hardware network appliances (routers, firewalls, load balancers, etc.) with software-based versions running as 
virtual machines or containers on standard commodity servers.

Why it matters:

Traditionally, each network function (firewall, load balancer, IDS) required its own physical box
NFV decouples the function from the hardware, so these functions run as Virtual Network Functions (VNFs) on generic infrastructure
Enables faster deployment, easier scaling, and lower hardware costs — you can spin up a new virtual firewall in minutes instead of ordering and racking a physical appliance

Related concept — SDN (Software-Defined Networking): Often paired with NFV. SDN separates the network's control plane (decision-making) from the data 
plane (actual packet forwarding), allowing centralized, programmable control of the network via software rather than manual configuration of individual devices.

Used heavily by: Telecom providers (virtualizing core network functions for 5G), cloud data centers. 

VPC (Virtual Private Cloud)

What it is: A logically isolated, private section of a public cloud (AWS, Azure, GCP) where you can launch resources (servers, databases, etc.) within a network 
you define and control — even though it's running on shared physical infrastructure.

Key features:

You define your own IP address range (CIDR block), subnets, route tables, and gateways
Can create public subnets (internet-accessible) and private subnets (isolated, no direct internet access)
Supports security controls like security groups (instance-level firewalls) and network ACLs (subnet-level firewalls)
Can connect to on-premises networks via VPN or dedicated connections (e.g., AWS Direct Connect)
Essentially gives you the isolation and control of a private data center network, but built on public cloud infrastructure

Analogy: It's like renting a private, fenced-off section of a shared building, where you decide the internal layout, who can enter, and how it connects to the outside world.

Cloud Service Models: IaaS, PaaS, SaaS

These describe how much of the technology stack the cloud provider manages versus what you manage yourself.

IaaS (Infrastructure as a Service)
Provider gives you the raw building blocks: virtual machines, storage, networking
You manage: OS, runtime, applications, data
Provider manages: physical hardware, virtualization, storage, networking infrastructure
Examples: AWS EC2, Google Compute Engine, Azure Virtual Machines
Best for: maximum control and customization, migrating existing on-prem infrastructure to the cloud
PaaS (Platform as a Service)
Provider gives you a ready-to-use platform to build, deploy, and run applications, without managing the underlying servers or OS
You manage: just your application code and data
Provider manages: OS, runtime, middleware, servers, scaling
Examples: Heroku, Google App Engine, Azure App Service, AWS Elastic Beanstalk
Best for: developers who want to focus purely on writing code without infrastructure overhead
SaaS (Software as a Service)
Provider delivers a complete, ready-to-use application over the internet — you just use it
You manage: nothing but your usage/data within the app
Provider manages: everything (infrastructure, platform, application, updates)
Examples: Gmail, Google Docs, Slack, Salesforce, Netflix
Best for: end users/businesses who just need the functionality, not the technical stack behind it

Memory trick: IaaS = rent the land, PaaS = rent a furnished apartment, SaaS = stay at a hotel (everything done for you).

Ports

What they are: A 16-bit number (ranging from 0 to 65535) that identifies a specific process or service running on a device, allowing a single IP address to handle 
many simultaneous connections for different purposes. A port combined with an IP address forms a socket — the full address used to route data to the correct application.

Port ranges:

Well-known ports (0–1023) — reserved for standard, widely used services
Registered ports (1024–49151) — assigned to specific applications by IANA, but not as strictly controlled
Dynamic/private ports (49152–65535) — used for temporary, client-side connections (ephemeral ports)

Common well-known ports:

Port	Service
20/21	FTP (data/control)
22	SSH
23	Telnet
25	SMTP (email sending)
53	DNS
67/68	DHCP
80	HTTP
110	POP3
143	IMAP
443	HTTPS
3306	MySQL
3389	RDP
5432	PostgreSQL

How it works in practice: When your browser connects to a website, it sends a request from a random ephemeral port on your machine to port 443 (HTTPS) on the server. 
The server knows to hand that request to its web application because of the destination port; your machine knows which browser tab to route the response back to because of the source port.

Firewalls and ports: A major part of firewall configuration is opening or blocking specific ports — e.g., blocking port 23 (insecure Telnet) while allowing port 22 (encrypted SSH).

GRE (Generic Routing Encapsulation)

What it is: A tunneling protocol developed by Cisco (now an open standard, RFC 2784) that encapsulates a wide variety of network layer protocols inside virtual 
point-to-point links over an IP network. It essentially wraps one packet inside another so it can travel across a network that might not normally support the original packet's protocol.

How it works:

The original packet (the "payload," which could be IP, IPv6, or even non-IP protocols) is wrapped in a GRE header, and that whole thing is then wrapped in a new outer IP header
This creates a virtual "tunnel" between two endpoints, making the underlying network path transparent — the two ends behave as if directly connected
GRE itself uses IP protocol number 47

Key characteristics:

No encryption — GRE only encapsulates/tunnels traffic, it does not provide confidentiality, authentication, or integrity checking
Supports multicast and broadcast traffic through the tunnel (unlike plain IPsec, which is typically unicast-only) — this makes GRE popular for tunneling routing protocols 
that rely on multicast (like OSPF)
Adds overhead (typically 24 bytes) for the GRE + outer IP header

Common use case: Because GRE has no security, it's very frequently paired with IPsec — GRE creates the tunnel and carries dynamic routing protocols, while IPsec encrypts 
the GRE-encapsulated traffic. This combination is often called GRE over IPsec.

IPsec (Internet Protocol Security)

What it is: A suite of protocols that provides authentication, integrity, and encryption for IP traffic, operating at the network layer (Layer 3). Unlike SSL/TLS which 
secures a specific application connection, IPsec can secure all IP traffic between two points transparently.

Core protocols within the IPsec suite:

AH (Authentication Header) — provides authentication and integrity (ensures data hasn't been tampered with and confirms the sender's identity), but no encryption/confidentiality
ESP (Encapsulating Security Payload) — provides encryption (confidentiality) plus optional authentication and integrity; this is the far more commonly used protocol 
in practice, since AH alone offers no privacy
IKE (Internet Key Exchange) — handles the negotiation of security parameters and cryptographic keys (explained in detail below)

What IPsec guarantees:

Confidentiality — data is encrypted so eavesdroppers can't read it
Integrity — data can't be modified in transit without detection
Authentication — confirms both parties are who they claim to be
Anti-replay protection — sequence numbers prevent captured packets from being resent maliciously
IPsec Header

The structure depends on whether AH or ESP is used, and whether it's in transport or tunnel mode (covered next).

AH Header fields:

Next Header — identifies the protocol of the following data
Payload Length
Security Parameters Index (SPI) — identifies the security association (SA) in use
Sequence Number — for anti-replay protection
Authentication Data — the integrity check value (ICV), a cryptographic hash of the packet

ESP Header fields:

ESP Header (before the encrypted payload):
Security Parameters Index (SPI)
Sequence Number
Encrypted payload — the actual data, encrypted
ESP Trailer (after the payload, also encrypted): padding, padding length, next header
ESP Authentication Data (unencrypted, appended at the end): integrity check value covering the ESP header, payload, and trailer

Key difference: AH authenticates the entire packet including parts of the outer IP header (which is why AH breaks when NAT modifies that header — a well-known 
"NAT-AH incompatibility" issue). ESP only encrypts/authenticates the payload (and in tunnel mode, the inner IP header), which is why ESP works much better with 
NAT (often combined with NAT-Traversal / NAT-T, which wraps ESP in UDP port 4500).

Tunnel Mode (vs. Transport Mode)

IPsec can operate in two modes, which determine what gets protected:

Transport mode:

Only the payload (the data portion) of the original IP packet is encrypted/authenticated
The original IP header is preserved and used for routing
Used for end-to-end communication between two hosts (e.g., securing a direct connection between a client and server)
Less overhead, but exposes the original source/destination IPs

Tunnel mode:

The entire original IP packet (header + payload) is encrypted/authenticated and then encapsulated inside a new outer IP header
The original header is completely hidden inside the encrypted payload
Used for network-to-network or gateway-to-gateway communication — most common in site-to-site VPNs, where the outer header shows the VPN gateways' IPs while 
the original internal (private) IPs stay hidden and protected
More overhead due to the extra IP header, but provides greater security and is essential when connecting entire private networks over the public internet

IKE Phase 1 and Phase 2

IKE (Internet Key Exchange) is the protocol IPsec uses to negotiate security parameters and establish shared secret keys before any actual data encryption happens. 
It runs in two distinct phases.

IKE Phase 1

Goal: Establish a secure, authenticated channel between the two peers — this creates the ISAKMP SA (also called the IKE SA), which is used to protect the negotiations in Phase 2.

What happens:

The two peers negotiate and agree on IKE policy parameters: encryption algorithm (e.g., AES), hashing algorithm (e.g., SHA-256), authentication method 
(pre-shared key or certificates), and Diffie-Hellman group (for key exchange)
They perform a Diffie-Hellman key exchange to generate shared secret keying material without ever transmitting the actual key over the network
Both sides authenticate each other (proving identity via pre-shared key, digital certificates, etc.)

Two modes for Phase 1:

Main Mode — 6 messages exchanged, more secure, hides the identities of the peers (commonly used for site-to-site VPNs)
Aggressive Mode — only 3 messages, faster but less secure (identities exposed), often used when one peer has a dynamic IP (e.g., some remote-access VPNs)
IKE Phase 2

Goal: Negotiate the actual IPsec SAs (Security Associations) that will protect the real data traffic — this is where the AH/ESP parameters are agreed on.

What happens:

Uses the secure channel established in Phase 1 to negotiate the IPsec transform set (which encryption/authentication algorithms ESP or AH will actually use for data)
Agrees on the traffic to be protected (which subnets/hosts the tunnel covers)
Optionally performs Perfect Forward Secrecy (PFS) — an additional Diffie-Hellman exchange so that even if a key is later compromised, past sessions remain secure
Only one mode exists here: Quick Mode

Result: Two unidirectional IPsec SAs are created (one for inbound, one for outbound traffic), and actual encrypted data can now flow through the tunnel.

Summary flow: Phase 1 = "let's agree how to talk securely and prove who we are" → Phase 2 = "now let's agree how to actually protect the data" → Data transfer begins.

Traffic Delivery Methods: Unicast, Multicast, Anycast, Broadcast

These describe how a packet is addressed and delivered to one or more recipients.

Unicast

What it is: One-to-one communication — a single packet is sent from one source to exactly one specific destination.

The most common form of network communication (e.g., loading a webpage, sending an email)
Each device has its own unique IP address as the destination
Simple and efficient for direct communication, but inefficient if the same data needs to go to many recipients (you'd need a separate copy per recipient)
Multicast

What it is: One-to-many (or many-to-many) communication — a single packet is sent to a group of interested receivers, identified by a special multicast address, without 
needing to know each individual recipient's address.

Uses reserved address ranges: 224.0.0.0 – 239.255.255.255 for IPv4
Devices "join" a multicast group using IGMP (Internet Group Management Protocol); routers use protocols like PIM (Protocol Independent Multicast) to build efficient distribution trees
The sender transmits data once; the network replicates it only where needed (at branch points), rather than sending duplicate copies all the way from the source
Used for: IPTV, video conferencing, stock market data feeds, routing protocol updates (e.g., OSPF uses multicast addresses like 224.0.0.5)
Anycast

What it is: One-to-nearest communication — multiple servers share the same IP address, and the network routes each request to whichever instance is topologically "closest" 
(based on routing metrics, not necessarily physical distance).

Relies on routing protocols (typically BGP) to advertise the same IP prefix from multiple locations; routers naturally forward traffic toward the nearest advertised source
If one anycast node fails, traffic automatically reroutes to the next closest one — providing built-in redundancy and load distribution
Used for: DNS root servers (all 13 "root server" identities are actually hundreds of physical anycast instances worldwide), CDN edge server selection, DDoS mitigation services
Broadcast

What it is: One-to-all communication — a single packet is sent to every device on a local network segment.

Uses the limited broadcast address 255.255.255.255 (reaches all devices on the local subnet) or a directed broadcast (the subnet's broadcast address, e.g., 192.168.1.255 for a /24 network)
IPv4 only — IPv6 has no broadcast; it uses multicast instead for similar purposes
Every device on the segment must process the packet, which can create unnecessary load — this is why broadcasts don't cross routers by default (they stay within the local broadcast domain)
Used for: ARP requests ("who has this IP?"), DHCP discovery (a client broadcasting to find a DHCP server before it even has an IP)

Type	    Destinations	                    Example Use
Unicast	    One specific                        device	Web browsing
Multicast	A defined group	                    IPTV, video conferencing
Anycast	    Nearest of many identical servers	DNS root servers, CDNs
Broadcast	All devices on local segment	    ARP, DHCP discovery

Wireless Standards Overview

Wireless communication standards define how devices transmit data over radio frequencies without physical cables. The most relevant families for networking are IEEE 
802.11 (Wi-Fi) for local wireless networks and cellular standards (3G/4G LTE/5G) for wide-area mobile connectivity. Bluetooth, Zigbee, and NFC also fall under wireless 
standards but serve short-range/IoT use cases.

802.11 (Wi-Fi)

What it is: The IEEE standard family that defines wireless local area networking (WLAN) — what we commonly call "Wi-Fi." Each amendment to the standard improves speed, 
range, frequency use, or efficiency.

Key amendments over time:

Standard	Marketing Name	Year	Max Speed	Frequency Band
802.11b	    Wi-Fi 1 	    1999	11 Mbps	    2.4 GHz
802.11a	    Wi-Fi 2 	    1999	54 Mbps	    5 GHz
802.11g	    Wi-Fi 3 	    2003	54 Mbps	    2.4 GHz
802.11n	    Wi-Fi 4	        2009	600 Mbps	2.4 & 5 GHz
802.11ac	Wi-Fi 5	        2013	~3.5 Gbps	5 GHz
802.11ax	Wi-Fi 6 / 6E	2019	~9.6 Gbps	2.4, 5 GHz (6E adds 6 GHz)
802.11be	Wi-Fi 7	        2024	~46 Gbps 	2.4, 5, 6 GHz

Key technical concepts:

Frequency bands: 2.4 GHz has longer range but more interference (shared with Bluetooth, microwaves) and fewer non-overlapping channels; 5 GHz offers more channels and less 
interference but shorter range; 6 GHz (Wi-Fi 6E/7) adds a large amount of fresh, uncongested spectrum
MIMO (Multiple Input, Multiple Output) — uses multiple antennas to send/receive multiple data streams simultaneously, boosting throughput
MU-MIMO — allows an access point to communicate with multiple devices at once rather than one at a time
OFDMA (Orthogonal Frequency Division Multiple Access) — introduced in Wi-Fi 6, splits channels into smaller sub-channels so multiple devices can be served simultaneously in one 
transmission, improving efficiency in dense environments
Beamforming — focuses the wireless signal directionally toward a specific device rather than broadcasting equally in all directions
Channel width — wider channels (20/40/80/160 MHz) allow higher throughput but reduce the number of non-overlapping channels available

Security standards used alongside 802.11: WEP (obsolete, insecure) → WPA → WPA2 (AES-based, long the standard) → WPA3 (current, adds stronger encryption and protection against 
offline password-guessing attacks).

LTE (Long-Term Evolution)

What it is: A cellular network standard for wide-area mobile broadband, commonly marketed as "4G" (true 4G technically requires LTE-Advanced, but LTE is broadly branded as 4G).

Key characteristics:

Developed by 3GPP (3rd Generation Partnership Project), evolving from earlier 3G (UMTS/HSPA) networks
All-IP network architecture — unlike older 3G networks, LTE carries voice as data too (VoLTE — Voice over LTE) rather than using a separate circuit-switched voice network
Uses OFDMA for the downlink and SC-FDMA for the uplink for efficient spectrum use
Typical real-world speeds: tens to a few hundred Mbps downlink; theoretical peak with LTE-Advanced can reach ~1 Gbps
Operates across a wide range of licensed frequency bands (varies significantly by country/carrier)

Architecture basics:

eNodeB — the base station (cell tower) that devices connect to
EPC (Evolved Packet Core) — the core network handling mobility management, authentication, and routing traffic to the internet
UE (User Equipment) — the mobile device itself

Evolution context: 3G → 4G/LTE → 5G. 5G builds on similar core concepts but adds much higher frequency bands (including mmWave), massive MIMO, network slicing, and dramatically 
lower latency, targeting use cases like autonomous vehicles and industrial IoT in addition to faster mobile broadband.

IEEE Ethernet Standards (802.3)

What it is: The IEEE 802.3 family of standards defines wired Ethernet networking — the rules for how devices communicate over cabled LANs, covering speed, cabling type, and maximum 
distance.

Naming convention decoded (e.g., 1000BASE-T):

Number (1000) — speed in Mbps
BASE — baseband signaling (the entire cable's bandwidth is used for a single signal, as opposed to broadband)
Suffix (T, TX, SX, LX, etc.) — indicates the medium: T/TX = twisted-pair copper; SX = short-range multimode fiber; LX = long-range single-mode fiber

Other important 802.3-related standards:

802.3af / 802.3at / 802.3bt — Power over Ethernet (PoE, PoE+, PoE++), delivering electrical power over the same cable as data
802.1Q — VLAN tagging standard (technically 802.1, not 802.3, but essential to Ethernet switching)
802.3x — flow control (PAUSE frames)
Fiber Optic Communication

What it is: A transmission method that sends data as pulses of light through thin strands of glass or plastic fiber, rather than electrical signals through copper.

How it works: A transmitter (laser or LED) converts electrical signals into light pulses, which travel through the fiber core via total internal reflection (the light bounces 
along the core because the surrounding cladding has a different refractive index), and a receiver at the other end converts the light back into electrical signals.

Two main types:

Single-mode fiber (SMF):

Very thin core (~9 microns), allows only one path/mode of light to travel straight through
Uses laser light sources
Supports much longer distances (tens of kilometers, even 100+ km with amplification) with less signal loss
Used for: long-haul, carrier-grade, and high-speed backbone links

Multimode fiber (MMF):

Larger core (50 or 62.5 microns), allows multiple light paths/modes to travel simultaneously, bouncing at different angles
Uses LED or VCSEL light sources, cheaper equipment
Shorter range (typically up to 300–550 m depending on grade, due to modal dispersion — different light paths arrive at slightly different times)
Used for: shorter runs within data centers or buildings

Advantages of fiber over copper:

Much higher bandwidth potential
Immune to electromagnetic interference (EMI)
Signal travels much further before needing regeneration
More secure — much harder to tap without detection
No electrical conductivity — safe in environments with lightning risk or explosive materials

Disadvantages: More expensive equipment, more fragile (glass can crack), requires precise/specialized termination and splicing tools, harder to install than copper.

Twisted Pair Copper Cable

What it is: The most common cabling for LANs, consisting of pairs of insulated copper wires twisted together. Twisting cancels out electromagnetic interference (EMI) and crosstalk 
between adjacent pairs — the tighter the twist, the better the interference cancellation and the higher the supported speed/category.

Types:

UTP (Unshielded Twisted Pair) — no additional shielding, relies purely on the twisting; cheaper, more flexible, most common in offices/homes
STP (Shielded Twisted Pair) — adds a metallic shield (foil or braid) around the pairs or the whole cable for extra protection against EMI; used in electrically noisy 
environments (factories, near heavy machinery)

Connector: Almost always terminated with an RJ45 connector.

Limitation: Maximum recommended run length is 100 meters for standard Ethernet over copper before signal degradation becomes a problem — beyond that, fiber or repeaters are needed.

Coaxial Cable

What it is: A cable with a single central copper conductor, surrounded by an insulating layer, a metallic shield (braided or foil), and an outer protective jacket — all arranged 
concentrically ("coaxial" = sharing the same axis).

Structure (inside to outside):

Center conductor (carries the signal)
Dielectric insulator
Metallic shield (protects against EMI, also carries the return signal/ground)
Outer plastic jacket

Why it matters historically: Was the backbone of early Ethernet (10BASE2 "thinnet," 10BASE5 "thicknet") before twisted pair took over for LANs.

Modern uses:

Cable television (CATV) distribution
Cable internet (DOCSIS standard, used by cable ISPs)
Connecting antennas/satellite dishes to receivers
Some specialized high-frequency/RF applications

Advantages: Good shielding against interference, supports reasonably high bandwidth, more resistant to interference than basic twisted pair.
Disadvantages: Bulkier and less flexible than twisted pair, largely replaced by fiber for high-capacity backbone links and by twisted pair for standard LAN wiring.

Twinaxial Cable (Twinax)

What it is: A cable similar in concept to coaxial, but with two central conductors (instead of one) running parallel within a shared shield, used to carry a 
balanced differential signal over short distances.

Key characteristics:

Provides high-speed, low-latency connections over short runs, typically up to about 5–10 meters (sometimes slightly more with active cables)
Much cheaper and less power-hungry than equivalent fiber optic transceivers over those short distances
Commonly comes as DAC (Direct Attach Copper) cables — pre-terminated with connectors (like SFP+, QSFP+) on both ends, ready to plug directly into switch/server ports

Common use cases:

Data center interconnects — connecting servers to top-of-rack switches, or switch-to-switch links within the same rack or adjacent racks
Used extensively for 10GbE, 25GbE, 40GbE, and 100GbE short-reach connections where the distance doesn't justify the cost of fiber + optical transceivers

Trade-off vs. fiber: Twinax is cheaper and simpler for short distances, but fiber is required once you need to span longer distances (beyond a rack or a few racks) or 
need immunity from EMI over longer stretches.
